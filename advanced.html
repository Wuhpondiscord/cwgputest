Browser-local performance and portable checkpoint tests. Nothing is sent to a server. Export/import is manual.

Configuration

Each trial validates the complete GPU output. Workload: 1.0 added per element per dispatch.

Automated full test suite

One click runs all local benchmark groups sequentially: dispatch modes, original chunk and state scaling, checkpoint frequency, optimized capture methods, larger-state comparisons, validated checkpoint intervals, and checkpoint restore plus resumed GPU work.

Uses your Trials and Warmups settings. The suite checks GPU outputs, shows progress, and makes a combined JSON export available, including partial results if a test fails. The every-16 frequency test uses at least 32 dispatches. Cross-browser transfer cannot run automatically without a second browser/node; the restore-and-resume check runs locally. For a shorter run, choose fewer trials.

1. Dispatch batching and synchronized readback

Same shader, inputs, dispatch count, and final validation; compare separate queue submissions, one batched submission, and intermediate readback after every dispatch.

2. Checkpoint chunk scaling

Compare 1, 4, 16, and 64 chunks for the same buffer size. Each snapshot is restored and checked.

3. Larger state scaling

Checkpoint 65,536, 131,072, 262,144, and 500,000 elements (256 KiB to approximately 1.91 MiB).

4. Checkpoint frequency

Compare no intermediate checkpoint, every 16, every 4, and every dispatch. Snapshots are read to CPU and discarded, while GPU execution continues.

5. Portable cross-browser checkpoint

Export a validated, versioned checkpoint with raw float32 state and a SHA-256 digest; transfer the file to a second browser or device and import it to restore into a new GPUBuffer and verify the results.

Manual file transfer only. This captures buffer contents and progress, not complete shader pipelines or arbitrary live execution.

6. Checkpoint capture strategies (new)

Test the same state with 1, 4, 16, and 64 chunks using three capture approaches: sequential copy/map per chunk, batched GPU copies with one submission and concurrent mapping, and one GPU readback followed by CPU-side chunking. Every result is restored to a new GPU buffer and checked element by element.

Reports snapshot, CPU splitting, restoration, verification times, GPU submissions, mapping calls, and validation. This isolates synchronization strategy rather than network transport. With default settings, this runs 12 configurations per trial.

7. State size × capture strategy

Measure 256 KiB, 512 KiB, 1 MiB, and ~1.91 MiB using one full sequential readback, 16 batched staging-buffer copies, and one readback plus CPU-side splitting into 16 chunks. Validates the restored GPU contents on every trial.

12 combinations per trial. This tests whether buffer size changes the synchronization-dominated results.

8. Intermediate checkpoint frequency (validated)

Compare no intermediate checkpoints against every 16, 4, or 1 dispatch. Validate every intermediate checkpoint and the final GPU result; do not count a final-dispatch checkpoint twice. Results include checkpoint counts, bytes, cumulative checkpoint time, and total elapsed time.

With 16 dispatches, an interval of 16 produces zero intermediate checkpoints because all modes already read the final output. Choose 32 or 64 dispatches for a nonzero every-16 checkpoint count.

9. Resume GPU computation from imported checkpoint

Import a checkpoint produced by test 5, verify the saved SHA-256, restore GPU state, validate it, then run extra GPU dispatches and validate the resumed result against the expected execution progress.

Uses the checkpoint file selected in section 5. To test between browsers, move the file manually. This resumes the deterministic vector-add workload, not arbitrary shader program counters.
